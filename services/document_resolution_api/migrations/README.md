
# Alembic Migrations

This folder contains the database migration repo for the **public\_api** service.

* `env.py` – Alembic environment; wires SQLAlchemy metadata and DB URL.
* `script.py.mako` – Template used when new revisions are generated.
* `versions/` – Your actual migration scripts (one file per revision).

## How it’s wired

* `alembic.ini` lives at `services/public_api/alembic.ini`.
* Inside the API container, paths are:

  * INI: `/app/public_api/alembic.ini`
  * Migrations: `/app/public_api/migrations`
* In `alembic.ini`:

  ```ini
  [alembic]
  script_location = %(here)s/migrations
  prepend_sys_path = %(here)s/../src
  sqlalchemy.url =
  ```

  `env.py` reads the real DB URL from your `.env` via the `Settings` class.

## Typical commands (Docker-first)

From your repo root, use the service Makefile shortcuts:

Makefile location: `services/document_resolution_api/Makefile`

* Apply latest migrations:

  ```bash
  make -C services/public_api migrate
  ```
* Create a new (autogenerated) revision:

  ```bash
  make -C services/public_api makemigration msg="your concise message"
  ```
* Roll back N steps (default 1 if n not provided):

  ```bash
  make -C services/public_api downgrade n=1
  ```
* (Optional) Seed example data:

  ```bash
  make -C services/public_api seed-local
  ```

These run **inside** the `api` container so the DB host `db` resolves and the Docker `.env` is used.

## Authoring tips

* Prefer `--autogenerate`, then **review the diff** before committing.
* Keep migration scripts deterministic/idempotent; avoid app logic.
* Name constraints/indexes explicitly to keep diffs stable.

## Common pitfalls

* **“No 'script\_location' key found”**
  You pointed Alembic at the wrong ini path. Use `-c public_api/alembic.ini` (container path) or `make migrate`.

* **“Path doesn’t exist: … migrations ; not …”**
  Inline comments after the value in `alembic.ini` are parsed as part of the path. Put comments on their own lines.

* **“Temporary failure in name resolution”**
  You ran migrations/seed on the host while `DATABASE_URL` points at `@db:5432/3`. Either:

  * run via `make` (inside the container), or
  * override to `@127.0.0.1` for host runs.
  * Or adjust the port according to your choice

## Linters/formatters

Exclude `migrations/` from auto-fixers (Ruff/whitespace hooks) to avoid churn. Example in your `.pre-commit-config.yaml`:

```yaml
exclude: ^services/public_api/migrations/
```
